## RESUMEN EJECUTIVO

La venta local permite crear bonos directamente sin pasar por WooCommerce.
Usa un carrito temporal (state.lvCart) y guarda en Firestore con código LOC-.
FALTA campo estado_pago (pagado/pendiente) para control financiero.

================================================================================
## FLUJO DE VENTA LOCAL
================================================================================

1. Usuario abre modal "Nueva Venta Local"
2. Busca producto en catálogo o crea personalizado
3. Selecciona pax, sesiones, descuento
4. Añade al carrito → addToCartLocal()
5. Puede añadir extras → addExtraToCart()
6. Introduce datos cliente (nombre, teléfono, email)
7. Crea bono → createLocalVoucher()

================================================================================
## ESTRUCTURA DEL CARRITO (state.lvCart)
================================================================================

Cada item del carrito contiene:

| Campo            | Tipo     | Descripción                         |
|------------------|----------|-------------------------------------|
| name             | string   | Nombre del producto (con dto si hay)|
| price            | number   | Precio final calculado              |
| sessions         | number   | Número de sesiones seleccionadas    |
| pax              | number   | Personas                            |
| originalProduct  | object   | Referencia al producto del catálogo |
| items_breakdown  | array    | Desglose de items del pack          |
| discount_percent | number   | Porcentaje de descuento aplicado    |
| added_at         | string   | Timestamp de adición (ISO)          |

================================================================================
## CÁLCULO DE PRECIO (addToCartLocal líneas 4711-4726)
================================================================================

Para producto personalizado (custom=true):
  price = valor del input lv-price

Para producto del catálogo:
  basePrice = state.lvSelectedProductBasePrice
  basePax = state.lvSelectedProductBasePax
  ratio = pax / basePax
  calculatedPrice = basePrice × ratio × (1 - discount/100)

⚠️ PROBLEMA: sesiones NO multiplican el precio
  - Si usuario compra 3 sesiones de masaje a 50€
  - El precio guardado es 50€, no 150€
  - El total se calcula en createLocalVoucher sumando (price × sessions)

================================================================================
## DESGLOSE DE ITEMS (items_breakdown)
================================================================================

Si el producto tiene items_incluidos (es un pack):
  - Se divide el precio entre número de items
  - Cada item hereda el pax seleccionado
  - Se detecta espacio con getSpaceForService()

Para servicios individuales:
  - Un solo item con name, sessions=1, space, pax, price

Estructura de cada item:
{
  name: string,
  sessions: number,  // Siempre 1 por item base
  space: string,
  pax: number,
  price: number,     // Precio prorrateado
  original_id: string|null
}

## CREACIÓN DEL BONO (createLocalVoucher líneas 4846-4957)
================================================================================

Datos que se guardan en spa_vouchers:

| Campo               | Valor                                    |
|---------------------|------------------------------------------|
| bono                | LOC-{año}-{aleatorio 4 dígitos}          |
| codigo              | Mismo que bono                           |
| cliente             | Input lv-client                          |
| email               | Input lv-email                           |
| telefono            | Input lv-phone                           |
| producto            | Nombres concatenados con " + "           |
| precio              | Suma de (price × sessions) del carrito   |
| importe             | Igual que precio                         |
| fecha               | Ahora (ISO)                              |
| estado              | 'pending' (SIEMPRE)                      |
| origen              | 'local'                                  |
| sesiones_totales    | Suma de sessions del carrito             |
| sesiones_usadas     | 0                                        |
| pax_por_sesion      | Máximo pax de los items                  |
| items_desglosados   | Fusión de breakdowns × sesiones          |
| discount_percent_max| Máximo descuento aplicado                |
| discount_total_amount| Suma de diferencia sin descuento        |
| manual_update       | true                                     |
| searchTokens        | Generados para búsqueda                  |

================================================================================
## CAMPOS FALTANTES PARA MODELO OPERATIVO
================================================================================

1. estado_pago: string enum
   - "pagado": Cliente ya pagó
   - "pendiente": Falta cobrar
   - "parcial": Pagó una señal

2. metodo_pago: string
   - "efectivo", "tarjeta", "transferencia", "bizum"

3. importe_pagado: number
   - Cantidad ya cobrada (para pagos parciales)

4. fecha_pago: string
   - Cuándo se recibió el pago

5. notas_venta: string
   - Observaciones del vendedor

================================================================================
## EXTRAS (COMPLEMENTOS)
================================================================================

Función: addExtraToCart() (líneas 4989-5024)

Los extras se cargan de spa_complementos y se añaden al carrito como items
individuales con:
  - name: nombre del complemento
  - price: precio del complemento
  - sessions: 1
  - pax: 1
  - isExtra: true (identificador)

⚠️ Los extras se suman al total correctamente

================================================================================
## PERSISTENCIA Y SINCRONIZACIÓN
================================================================================

1. Guardado local inmediato (IndexedDB via apiLocal)
   - syncStatus: 'pending'

2. Intento de sincronización a Firestore
   - Si falla, queda en local con status 'offline'
   - Si OK, marca como 'synced'

3. Función uploadLocalPendingToFirestore() para reintentar

================================================================================
## INCONSISTENCIAS DETECTADAS
================================================================================

1. estado siempre 'pending'
   - No hay forma de marcar como "pagado" vs "por cobrar"
   - Todo bono local empieza equal

2. Código puede colisionar
   - LOC-{año}-{4 dígitos aleatorios}
   - Con 9999 bonos/año hay colisión posible

3. telefono obligatorio pero validación débil
   - Se marca en rojo pero no hay regex

4. Email no obligatorio
   - Para PDF y notificaciones podría ser problema

5. items_desglosados multiplica mal
   - Si compra 3 sesiones, crea 3 copias del breakdown
   - Cada copia tiene used=0, correcto
   - Pero precio de cada item sigue siendo precio/itemCount (no ×3)
