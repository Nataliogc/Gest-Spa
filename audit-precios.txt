## FUENTES DE PRECIO DETECTADAS

### 1. WOOCOMMERCE (wordpress-bonos-plugin.php)
   Línea: 86, 91
   Campo: $item->get_total() (precio por línea después de descuentos)
   Se exporta como: 'precio' => $total_price, 'importe' => $total_price
   
   ✅ CORRECTO: Usa el total del item (después de descuentos).
   ⚠️  NOTA: Si hay múltiples items en un pedido, se SUMAN correctamente (L91).

### 2. SINCRONIZACIÓN (js/bonos.js - sincronizarConTienda)
   Líneas: 1481-1522
   
   Lógica: Busca precio en múltiples campos:
     1. b.precio || b.importe
     2. b.total || b.item_total || b.amount || b.line_total || b.subtotal
     3. b.order_total || b.price || b.value || b.order_subtotal
     4. line_items[].total (suma)
     5. items_desglosados[].precio (suma)
   
   ⚠️  DISCREPANCIA DETECTADA:
   - Si order tiene descuento y foundPrice > orderTotal, usa orderTotal (L1514-1517)
   - Esto puede causar que items_desglosados tengan precios brutos pero el bono tenga precio neto

### 3. CATÁLOGO (catalogo.html / spa_services)
   Campo: precio (input sm-precio)
   
   Se usa como FALLBACK cuando b.importe es 0 (L2462-2474 en bonos.js)
   
   ⚠️  PROBLEMA GRAVE:
   El cálculo aplica multiplicadores:
     displayedPrice = catalogMatch.precio * (paxRatio * sessionsRatio)
   
   Esto puede dar precios INCORRECTOS si:
     - El producto catálogo es para 1 persona pero el bono es para 2
     - El bono tiene 5 sesiones pero el catálogo define 1

### 4. VENTA LOCAL (js/bonos.js - selectProductForLocalVoucher)
   Líneas: 4448-4578
   
   Usa: prod.precio del catálogo
   Almacena: state.lvSelectedProductBasePrice, state.lvSelectedProductBasePax
   
   Recalcula en updateLocalPriceWithDiscount (L4660-4690):
     finalPrice = basePrice * (currentPax / basePax) * (1 - discount/100)
   
   ✅ Lógica correcta de prorrateo por pax
   ⚠️  No considera sesiones (solo pax)

### 5. VISUALIZACIÓN EN TABLA (renderBonosFromState)
   Líneas: 2462-2483
   
   displayedPrice = parseFloat(b.importe) || 0
   
   Si es 0, aplica FALLBACK con catálogo:
     basePrice * paxRatio * sessionsRatio
   
   ⚠️  El ratio puede causar precios inflados si el catálogo tiene producto "base"
   
### 6. PDF DE BONO (js/bono-pdf.js)
   ❌ NO MUESTRA PRECIO EN NINGÚN LUGAR DEL PDF
   
   Solo incluye: código, nombre cliente, mensaje, items, fechas

## DISCREPANCIAS ENCONTRADAS
================================================================================

| Origen           | Campo Usado      | Lógica de Cálculo                    |
|------------------|------------------|--------------------------------------|
| WooCommerce      | item.total       | Suma de totales netos               |
| Sincronización   | precio/importe   | Detecta mejor campo disponible      |
| Tabla            | b.importe        | Fallback: catalogo * pax * sessions |
| Venta Local      | prod.precio      | catalogo * paxRatio - descuento     |
| Modal Gestión    | updatePriceBadge | Recálculo dinámico complejo         |
| PDF              | (ninguno)        | No muestra precio                   |

PROBLEMA 1: Campo duplicado precio/importe
  - WooCommerce envía ambos con el mismo valor
  - Localmente se pueden desincronizar

PROBLEMA 2: Fallback catalog multiplier
  - Si el bono tiene importe=0 pero es un pack, el multiplicador
    da precio incorrecto (multiplica precio unitario × sesiones totales del bono)

PROBLEMA 3: Extras/Complementos
  - Los complementos tienen precio en spa_complementos.precio
  - Al añadir extras en carrito local, su precio se suma correctamente
  - Pero al sincronizar de WooCommerce, los extras se tratan como items normales

================================================================================

   - Calculado una sola vez durante sincronización

2. ELIMINAR DUPLICADO: precio/importe
   - Usar solo "precio" en todo el código
   - Deprecar "importe"

3. CORREGIR FALLBACK DE CATÁLOGO:
   - No multiplicar por sesiones si el bono ya tiene precio válido
   - El multiplicador solo aplica si precio original es 0

4. MOSTRAR PRECIO EN PDF:
   - Añadir precio_final en bono-pdf.js línea ~160

5. NORMALIZAR ITEMS_DESGLOSADOS:
   - Usar siempre "precio" (no "price", "total", etc.)
   - Cada item debe tener: { name, precio, pax, sessions }
