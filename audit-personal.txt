================================================================================
## CAMPOS FALTANTES PARA MODELO OPERATIVO
================================================================================

1. skills: string[]
   - Lista de categorías de servicio que puede realizar
   - Ejemplo: ["masaje", "facial", "ritual", "corporal"]
   - SIN ESTO no se puede validar terapeuta ↔ servicio

2. certifications: object[]
   - Certificaciones oficiales
   - { name: "Masaje Deportivo", expiry: "2026-12-31" }

3. preferredRooms: string[]
   - Salas preferidas (para optimización de asignación)

4. maxDailyAppointments: number
   - Límite de citas por día (evitar fatiga)

5. specialties: string[]
   - Servicios en los que destaca (para sugerencias)

================================================================================
## MATCHING TERAPEUTA → SERVICIO (ACTUAL)
================================================================================

Flujo actual en reservas:
1. Usuario selecciona servicio
2. Sistema busca sala compatible (allowedSpaces del servicio)
3. Sistema busca terapeuta disponible (assigned_rooms incluye sala)
4. NO valida si terapeuta sabe hacer el servicio

⚠️ PROBLEMA CRÍTICO:
  Un terapeuta asignado a Panacea puede aparecer como disponible
  para un servicio de "Ritual Facial" aunque no tenga la skill.

================================================================================
## FLUJO ACTUAL DE ASIGNACIÓN (reservas-staff.js)
================================================================================

getAvailableStaffForRoom(roomCode, date, startTime, endTime):
  1. Carga staff con assigned_rooms que incluya roomCode
  2. Verifica disponibilidad en esa fecha/hora
  3. Retorna lista de terapeutas disponibles

NO incluye:
  - Verificación de skill para el servicio
  - Verificación de certificaciones vigentes
  - Límite de citas diarias

## INCONSISTENCIAS DETECTADAS
================================================================================

1. assigned_rooms podría no existir en spa_spaces
   - No hay validación FK
   - Si se elimina una sala, assigned_rooms queda huérfano

2. No hay campo "skills" o "services"
   - Terapeuta de peluquería podría asignarse a masaje

3. Disponibilidad no se sincroniza automáticamente
   - Si terapeuta trabaja lunes-viernes según default_schedule
   - Pero sábado tiene "custom", la lógica es compleja

4. Notas por día no se muestran en reservas
   - Solo se ven en calendario de personal
