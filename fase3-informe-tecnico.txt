## 2. REPORT DE MATCHING (3 NIVELES)
================================================================================

### NIVEL 1: Servicio → Sala

Implementación: matchServiceToRooms(serviceId, date, time, options)

Flujo:
  1. Normaliza servicio (añade campos si faltan)
  2. Lee allowed_spaces del servicio
  3. Filtra salas por compatible_categories
  4. Verifica disponibilidad (max_concurrent)
  5. Aplica min_spacing entre reservas
  6. Retorna salas disponibles con metadata

Campos utilizados:
  - Servicio: allowed_spaces, categoria, duration_total
  - Sala: compatible_categories, max_concurrent, min_spacing

Resultado:
  {
    success: boolean,
    availableRooms: Space[],
    errors: string[],
    debug: string[]
  }

### NIVEL 2: Servicio → Terapeuta

Implementación: matchServiceToTherapists(serviceId, roomCode, date, time, duration)

Flujo:
  1. Verifica si servicio requires_therapist
  2. Si allowed_therapists definido, filtra solo esos IDs
  3. Filtra por assigned_rooms (sala compatible)
  4. Filtra por skills (categoría del servicio)
  5. Verifica horario (default_schedule + excepciones)
  6. Verifica conflictos con reservas existentes
  7. Retorna terapeutas disponibles

Campos utilizados:
  - Servicio: requires_therapist, allowed_therapists, categoria
  - Terapeuta: assigned_rooms, skills, default_schedule
  - Excepciones: spa_staff_availability

Resultado:
  {
    success: boolean,
    availableTherapists: Staff[],
    requiredCount: number,
    errors: string[],
    debug: string[]
  }

### NIVEL 3: Servicio → Pax

Implementación: matchServiceToPax(service, requestedPax)

Flujo:
  1. Lee modalidad del servicio
  2. Determina pax esperado según modalidad
  3. Compara con pax solicitado
  4. Permite flexibilidad en mixtos

Resultado:
  {
    valid: boolean,
    servicePax: number,
    requestedPax: number,
    modalidad: string,
    message: string
  }

## 3. VALIDACIÓN DE PACKS
================================================================================

Implementación: matchPackSequence(serviceId, date, startTime)

Flujo:
  1. Detecta servicio como modalidad "mixto"
  2. Ordena secuencia por campo "orden"
  3. Para cada fase:
     a. Calcula hora inicio (acumulativa)
     b. Matching Sala para espacio de fase
     c. Matching Terapeuta si requires_therapist
  4. Si TODAS fases disponibles → Pack reservable
  5. Genera ID de pack único

Estructura de fases procesadas:
  {
    orden: number,
    nombre: string,
    espacio: string,
    duracion: number,
    hora_inicio: string,
    hora_fin: string,
    requires_therapist: boolean,
    terapeutas_requeridos: number,
    room_available: boolean,
    therapists_available: Staff[]
  }

Generación de reservas vinculadas:
  - Cada fase genera 1 reserva en spa_bookings
  - Todas comparten pack_id
  - Cada una tiene fase_orden (1, 2, 3...)

  - Suite Romántica: modalidad=pareja, terapeutas=1 ✅

## 5. VALIDACIÓN DE ESTADO DE PAGO
================================================================================

Implementación: normalizeVoucherPayment(voucher, paymentData)

Estados soportados:
  - "pagado": importe_pagado = precio, importe_pendiente = 0
  - "pendiente": importe_pagado = 0, importe_pendiente = precio
  - "parcial": importe_pagado = input, importe_pendiente = precio - input

Métodos de pago soportados:
  - efectivo, tarjeta, transferencia, bizum

Campos añadidos al bono:
  - estado_pago: string
  - metodo_pago: string
  - importe_pagado: number
  - importe_pendiente: number
  - fecha_pago: string (ISO)
  - notas_venta: string
