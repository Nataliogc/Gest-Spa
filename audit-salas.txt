## COMPATIBILIDAD SERVICIO → SALA
================================================================================

Relación actual definida en SERVICIOS (no en salas):
  - spa_services.espacio: string (legacy, un solo espacio)
  - spa_services.allowedSpaces: string[] (nuevo, multi-select)

⚠️ PROBLEMA 1: No hay validación inversa
  - No se puede consultar "¿Qué servicios van en Panacea?"
  - Solo se puede consultar "¿En qué salas va este servicio?"

⚠️ PROBLEMA 2: No existe campo compatibleServices en sala
  - Esto dificulta el matching automático

⚠️ PROBLEMA 3: Capacidad no se usa en reservas
  - El campo capacity existe pero NO se valida al reservar
  - 25 personas podrían reservar Spa con capacity=20

================================================================================
## CAMPOS FALTANTES PARA MODELO OPERATIVO
================================================================================

1. compatibleServices: string[]
   - Lista de códigos de servicios/categorías permitidas en esta sala
   - Ejemplo para Panacea: ["masaje", "facial", "corporal", "ritual"]

2. requiresTherapist: boolean
   - true: Las reservas en esta sala necesitan terapeuta asignado
   - false: Autoservicio (spa, gimnasio)

3. assignableTherapists: string[]
   - IDs de terapeutas que pueden trabajar en esta sala
   - Ejemplo para Suite: ["terapeuta1", "terapeuta2"]

4. maxConcurrentBookings: number
   - Número máximo de reservas simultáneas
   - Para cabinas individuales = 1, para spa general = 10-20

5. equipmentRequired: string[]
   - Equipamiento especial de la sala
   - Útil para matching de tratamientos específicos

## USO DE SALAS EN EL SISTEMA
================================================================================

Archivos que usan spa_spaces:
  - js/config.js: CRUD de salas, render en configuración
  - personal.js: Carga salas para asignar a terapeutas
  - reservas.html: Filtro por tipo de sala (tipo implícito en URL)

⚠️ NOTA: No hay validación de capacidad en ningún archivo

## INCONSISTENCIAS DETECTADAS
================================================================================

1. Código duplicado en servicio y sala
   - espacio en servicio es string ("spa", "panacea")
   - code en sala es también string ("spa", "panacea")
   - No hay FK/relación formal, solo match por string

2. allowedSpaces en servicio vs compatibles en sala
   - Solo se define la relación UN MODO
   - No hay verificación cruzada

3. Tipos de sala genéricos
   - "other" es demasiado amplio
   - Restaurante y Gimnasio son muy diferentes pero tienen mismo tipo

   - Ejemplo Suite: ["masaje", "ritual", "pack_pareja"]

   - Impedir sobreventa de Spa si ya hay 20 personas
